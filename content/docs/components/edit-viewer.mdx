---
title: Edit Viewer
description: Renders a Retab edit result — source, preview, filled output, and detected form fields.
---

The edit viewer renders the output of a Retab **edit** beside its source
document: each detected form field is drawn as a bbox overlay on the page, and a
synced panel lists the fields with their inferred values. Hover or select a
field to highlight its region and scroll it into view. **Preview** stamps the
field values onto the source document as an overlay; **Filled** is reserved for
the actual generated output file when one is supplied. The panel groups fields
by page and supports search and filled/empty/type filtering.

## Composition

`EditViewerProvider` owns edit state. `ViewerRoot` owns sidebar state.
`EditViewerFields` is content-only, so put it inside `ViewerSidebar` when you
want the default field rail.

Do not wrap `EditViewerProvider` inside `ViewerRoot`; the provider should sit
outside the viewer layout so header, surface, and sidebar parts can all read the
same edit state.

```tsx
import {
  ViewerBody,
  ViewerRoot,
  ViewerSidebar,
  ViewerSurface,
} from "@/components/ui/viewer"
import {
  EditViewerDocument,
  EditViewerFields,
  EditViewerHeader,
  EditViewerProvider,
} from "@/components/viewers/edit/edit-viewer"
```

```tsx
<EditViewerProvider result={{ fields }} sourceDocument={sourceDocument}>
  <ViewerRoot bare defaultOpen>
    <EditViewerHeader />
    <ViewerBody>
      <ViewerSurface>
        <EditViewerDocument />
      </ViewerSurface>
      <ViewerSidebar aria-label="Document fields" side="right">
        <EditViewerFields />
      </ViewerSidebar>
    </ViewerBody>
  </ViewerRoot>
</EditViewerProvider>
```

Use `ViewerSidebarTrigger` anywhere inside `ViewerRoot` to toggle the field
sidebar. Use `useEditViewerDocument` for custom document rendering, and
`useEditViewerFields` for custom field panels.

## Easy API

Pass the edit result plus any available documents directly:
`result={{ fields }}`, `sourceDocument`, and `filledDocument`.

```tsx
<EditViewer
  result={{ fields }}
  sourceDocument={sourceDocument}
  filledDocument={filledDocument}
/>
```

The viewer derives valid `source`, `preview`, and `filled` modes from those
artifacts, defaults to the generated filled document when it exists, and falls
back safely as async artifacts load. Overlay rendering currently requires a PDF
source document; non-PDF filled outputs still render through the universal file
viewer.

Use `options` only when embedding a constrained variant, such as hiding search,
filters, the field panel, preview overlays, or filled-output mode.

## Controlled Mode

Use `mode` when another control owns the displayed document mode.
`undefined` leaves the mode uncontrolled. `null` is accepted as a controlled
fallback request: the viewer resolves the best available display mode without
calling `onModeChange`. `onModeChange` fires only for user-initiated mode
changes.

## Controlled Selection

Use `selectedFieldKey` and `onSelectedFieldKeyChange` to own the committed field
selection. Hover previews update the visual highlight without committing
selection. If a controlled key no longer exists in the normalized fields, the
viewer clears it with `onSelectedFieldKeyChange(null)`.

## Field Panel Disabled

Disable the default field rail when the host layout provides its own field
navigation or only needs the document surface.

```tsx
<EditViewer
  result={{ fields }}
  sourceDocument={sourceDocument}
  options={{ fieldPanel: false }}
/>
```

## Custom Field Panel

Use the composed API when the field panel needs custom placement or rendering.
`useEditViewerFields` returns the same field projection and selection callbacks
used by `EditViewerFields`.

```tsx
function CustomFields() {
  const fields = useEditViewerFields()

  return fields.visibleFields.map((field) => (
    <button key={field.key} onClick={() => fields.selectField(field.key)}>
      {field.key}
    </button>
  ))
}
```

## Data Contract

`sourceDocument` and `filledDocument` use `EditViewerDocumentSource`: `src` or
`buffer`, a required `mimeType`, and an optional `filename`. Field bboxes are
1-based by page and normalized page-relative values. Invalid boxes become
unlocated fields instead of errors.
