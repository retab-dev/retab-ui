title: Sidebar
description: App-shell sidebar primitives for persistent navigation, menus, rails, and responsive mobile projection.

`SidebarProvider` and `Sidebar` are the app-shell sidebar system. Use them for
application navigation: persistent open state, mobile sheet projection, the
global sidebar shortcut, rails, grouped menus, menu buttons, actions, badges,
and skeleton rows.

They are not viewer layout primitives and they are not domain sidebars.

## Architecture Boundary

Use the exact primitive for the ownership layer:

- `SidebarProvider` and `Sidebar` own app navigation.
- `ViewerSidebar` owns a spatial rail inside `ViewerBody`.
- `SidebarList*` owns providerless grouped-row grammar inside domain
  components, modals, cards, and viewer rails.
- `SegmentSidebar` owns segment row state and segment interaction semantics.
- `AttachmentSidebar` owns file attachment rows.

Do not mount `SidebarProvider` inside `ViewerSidebar` just to get grouped rows.
Use `SidebarList*` for that shape.

## Usage

```tsx
<SidebarProvider>
  <Sidebar>
    <SidebarHeader />
    <SidebarContent>
      <SidebarGroup>
        <SidebarGroupLabel>Workspace</SidebarGroupLabel>
        <SidebarGroupContent>
          <SidebarMenu>
            <SidebarMenuItem>
              <SidebarMenuButton isActive>Documents</SidebarMenuButton>
            </SidebarMenuItem>
          </SidebarMenu>
        </SidebarGroupContent>
      </SidebarGroup>
    </SidebarContent>
  </Sidebar>
  <SidebarInset>{children}</SidebarInset>
</SidebarProvider>
```

## Viewer Rails

Viewer rails use viewer primitives instead:

```tsx
<ViewerRoot>
  <ViewerHeader />
  <ViewerBody>
    <ViewerSidebar aria-label="Pages">
      <PageRail />
    </ViewerSidebar>
    <ViewerSurface>
      <Document />
    </ViewerSurface>
  </ViewerBody>
</ViewerRoot>
```

The app sidebar and viewer sidebar systems share visual tokens, but they do not
share ownership.

## Structural Attributes

Viewer primitives expose stable structural attributes:

- `data-slot` identifies the structural primitive for tests and local styling.
- `data-viewer-sidebar-*` identifies sidebar open state, mode, and transition
  readiness.

Viewer primitives do not encode domain purpose. Put that meaning in the named
domain part (`SplitViewerPageRail`, `EmailViewerPartsList`) and in accessible
labels (`aria-label="PDF pages"`, `aria-label="Email parts"`).
