`FileViewerSurface` is the primary content slot inside `FileViewerBody`. In the
common composition it contains `FileViewerDocument`, but it can also wrap a
domain-owned file surface.

```tsx
<FileViewerSurface>
  <FileViewerDocument />
</FileViewerSurface>
```

It can also host a renderer's own surface instead of the routed document — for
example a provider-bound PDF page list:

```tsx
<FileViewerSurface>
  <PdfViewerPages />
</FileViewerSurface>
```

## Behavior

- Renders a `data-slot="file-viewer-surface"` region that takes the space beside
  the sidebar and scrolls its own content.
- It holds exactly one file surface. Split panes and side-by-side comparisons
  belong to the parent workflow, not to a second surface inside one body.
- It is layout only — it does not read the file source. The content it wraps
  (the routed document, or a renderer surface) owns rendering.

## API Reference

| Prop       | Type                                         | Description                                          |
| ---------- | -------------------------------------------- | ---------------------------------------------------- |
| `children` | `React.ReactNode`                            | The file surface, usually `FileViewerDocument`.      |
| `...props` | `React.ComponentProps<typeof ViewerSurface>` | Standard surface props; `className` is forwarded.    |
