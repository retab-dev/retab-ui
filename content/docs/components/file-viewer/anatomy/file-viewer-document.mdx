`FileViewerDocument` renders the active file route. It is the leaf that chooses
PDF, image, CSV, text, Markdown, HTML, email, Office, or another supported
renderer from the current `FileViewer` source.

```tsx
<FileViewerSurface>
  <FileViewerDocument />
</FileViewerSurface>
```

## Behavior

- Reads the resolved source from context and dispatches to the matching
  renderer. Unsupported types fall back to a download card.
- Renderers are **lazy-loaded** — only the one your file needs is fetched, so a
  PDF page never ships the spreadsheet engine.
- Renders behind `Suspense` (showing a category-shaped skeleton while the
  renderer loads) and an error boundary that resets when the file changes.
- Keep renderer-specific controls inside the renderer. They register upward and
  appear through `FileViewerControls`, so the document needs no control props.

## API Reference

| Prop        | Type     | Description                                          |
| ----------- | -------- | ---------------------------------------------------- |
| `className` | `string` | Optional class on the rendered document container.   |
