File System turns an object-store manifest into a navigable document workspace.
It accepts flat file and folder records, infers folder chains, and presents the
same source set through list, grid, and columns views.

Use it when users need to browse generated documents, uploaded files,
extraction artifacts, or case workspaces with a file browser sidebar and a
selected-file viewer surface.

## Installation

```bash
pnpm dlx shadcn@latest add @retab/file-system
```

For the demo block:

```bash
pnpm dlx shadcn@latest add @retab/file-system-block
```

Open the full-page demo at [/view/blocks/file-system](/view/blocks/file-system).

```tsx
import {
  FileSystemBrowser,
  FileSystemHeader,
  FileSystemOpenPreview,
  FileSystemProvider,
  FileSystemPreview,
  type FileSystemItem,
} from "@/components/ui/file-system"
import {
  ViewerBody,
  ViewerSurface,
  ViewerHeader,
  ViewerSidebar,
  ViewerRoot,
} from "@/components/ui/viewer"

const items: FileSystemItem[] = [
  {
    kind: "file",
    path: "research/attention.pdf",
    mimeType: "application/pdf",
    source: {
      kind: "url",
      url: "/samples/attention.pdf",
      fileName: "attention.pdf",
      mimeType: "application/pdf",
    },
  },
]

export function Documents() {
  return (
    <FileSystemProvider items={items} title="Workspace">
      <ViewerRoot>
        <ViewerHeader>
          <FileSystemHeader />
        </ViewerHeader>
        <ViewerBody>
          <ViewerSidebar aria-label="Files">
            <FileSystemBrowser />
          </ViewerSidebar>
          <ViewerSurface>
            <FileSystemPreview />
          </ViewerSurface>
        </ViewerBody>
        <FileSystemOpenPreview />
      </ViewerRoot>
    </FileSystemProvider>
  )
}
```

The file-system composition has three product surfaces:

| Surface                 | Owns                                                               | Does not own           |
| ----------------------- | ------------------------------------------------------------------ | ---------------------- |
| `FileSystemBrowser`     | folder navigation, query, sort, view mode, lazy loading, selection | document rendering     |
| `FileSystemPreview`     | selected-entry preview, source resolution, file actions, metadata  | browser navigation     |
| `FileSystemOpenPreview` | double-click and keyboard-open modal lifecycle                     | selected preview state |

The provider owns the file-system domain state. The viewer primitives own
layout. `FileSystemPreview` resolves the selected entry to a `ViewerSource`
and renders files with `FileViewer`. `FileSystemOpenPreview` owns the explicit
open lifecycle: double-click or keyboard-open a file to show it in a modal.
`onFileOpen` observes that lifecycle; omit `FileSystemOpenPreview` when another
shell owns file opening.

## Usage

`FileSystem` is the easy API. It is the preassembled version of the composition
above.

```tsx
import { FileSystem, type FileSystemItem } from "@/components/ui/file-system"

export function EasyDocuments() {
  return <FileSystem items={items} title="Workspace" />
}
```

## Useful Behaviors

- Accepts a flat manifest and infers missing parent folders.
- Shares selection, preview, search, and sort state across list, grid, and
  columns views.
- Renders the list view with virtualized tree navigation, keyboard behavior,
  and icon handling.
- Uses `FileThumbnail` for compact previews and `FileViewer` for the selected
  file preview.
- Supports controlled `view`, `selectedPath`, and `query` state.
- Supports lazy folders through `loadChildren`.
- Resolves file sources on demand through `resolveSource`.
- Keeps explorer views as browsers only. The selected document preview belongs
  to `FileSystemPreview`.
- Uses `FileSystemOpenPreview` for built-in modal opening. Pass `onFileOpen`
  when app routing or analytics needs to observe file opening.

## Source Resolution

`FileSystem` resolves previews lazily. If a file already has a `source`, that
source is used directly. Otherwise `resolveSource` is called when the file is
selected or opened.

Resolved sources are cached by file path for the lifetime of the current
`items` identity. When you replace `items`, the cache is cleared before the next
preview resolution, so same-path files can point to updated sources after an
item refresh.

## Boundary Rules

- Use `FileSystem` for the canonical browser-plus-preview layout.
- Use `FileSystemProvider` and named parts when you need a custom viewer layout.
- Do not put file-system state into viewer primitives.
- Do not use `FileViewer` as a file browser; it renders one resolved source.
- Do not use `file-system-light` when folder, query, lazy loading, selected
  preview, or named-part composition is needed.
- `file-system-light` is a separate lightweight flat-file convenience
  component, not the canonical file-system architecture.

## API Reference

### Manifest Input

These props define the file-system product and its outer chrome.

| Prop        | Type               | Default | Required |
| ----------- | ------------------ | ------- | -------- |
| `items`     | `FileSystemItem[]` | `-`     | Yes      |
| `title`     | `string`           | `Files` | No       |
| `className` | `string`           | `-`     | No       |

### Browser State

These props control where the browser is, which view it uses, and how visible
entries are filtered and sorted.

| Prop            | Type                            | Default | Required |
| --------------- | ------------------------------- | ------- | -------- |
| `defaultPath`   | `string`                        | `""`    | No       |
| `path`          | `string`                        | `-`     | No       |
| `onPathChange`  | `(path) => void`                | `-`     | No       |
| `defaultView`   | `"list" \| "grid" \| "columns"` | `list`  | No       |
| `view`          | `"list" \| "grid" \| "columns"` | `-`     | No       |
| `onViewChange`  | `(view) => void`                | `-`     | No       |
| `defaultQuery`  | `Partial<FileSystemQueryState>` | `-`     | No       |
| `query`         | `Partial<FileSystemQueryState>` | `-`     | No       |
| `onQueryChange` | `(query) => void`               | `-`     | No       |

### Selection Control

Selection is browser state. The selected entry feeds `FileSystemPreview`, but
preview does not own selection.

| Prop                  | Type             | Default | Required |
| --------------------- | ---------------- | ------- | -------- |
| `selectedPath`        | `string \| null` | `-`     | No       |
| `defaultSelectedPath` | `string \| null` | `null`  | No       |
| `onSelectionChange`   | `(item) => void` | `-`     | No       |

### Loading And Source Resolution

Folder loading extends the manifest. Source resolution turns a file entry into
a `ViewerSource` only when a preview needs it.

| Prop            | Type                                              | Default | Required |
| --------------- | ------------------------------------------------- | ------- | -------- |
| `loadChildren`  | `(args) => Promise<FileSystemLoadChildrenResult>` | `-`     | No       |
| `resolveSource` | `(args) => Promise<ViewerSource \| null>`         | `-`     | No       |

### Open Events

`FileSystemOpenPreview` owns the explicit open lifecycle. `onFileOpen` observes
successful file opens after source resolution.

| Prop         | Type                     | Default | Required |
| ------------ | ------------------------ | ------- | -------- |
| `onFileOpen` | `(file, source) => void` | `-`     | No       |

### Render Extensions

These extension points decorate previews. They do not change browser state.

| Prop                | Type                        | Default | Required |
| ------------------- | --------------------------- | ------- | -------- |
| `renderFileActions` | `(file) => React.ReactNode` | `-`     | No       |
| `renderMetadata`    | `(item) => React.ReactNode` | `-`     | No       |
