Renders a Retab split result: named subdocuments, each owning a set of pages.

<ComponentPreview name="split-viewer-demo" />

## Viewer Composition

Compose split results from the split provider, the shared viewer layout
primitives, and the named split parts that encode split behavior. The
`document` prop is the only required extension point: it renders the source
document and connects document page events back to split navigation with
`useSplitViewerDocumentControls`.

```tsx
function SplitDocument() {
  const controls = useSplitViewerDocumentControls()

  return (
    <PdfViewerPages
      ref={controls.setDocumentHandle}
      bare
      className="h-full"
      onVisiblePageChange={controls.onCurrentPageChange}
      onScrollProgressChange={controls.onScrollProgressChange}
    />
  )
}

export function Example() {
  return (
    <SplitViewerProvider result={result}>
      <FileViewer source={source} defaultOpen>
        <PdfViewerProvider>
          <FileViewerHeader>
            <FileViewerSidebarTrigger />
            <FileViewerTitle />
            <SplitViewerHeaderMeta />
            <FileViewerControls />
          </FileViewerHeader>
          <FileViewerBody>
            <SplitViewerSidebar>
              <SplitViewerPageRail />
            </SplitViewerSidebar>
            <FileViewerSurface>
              <SplitViewerLegend />
              <SplitViewerDocument document={<SplitDocument />} />
            </FileViewerSurface>
          </FileViewerBody>
        </PdfViewerProvider>
      </FileViewer>
    </SplitViewerProvider>
  )
}
```

`FileViewerHeader` owns the full-width file row. `SplitViewerHeaderMeta` contributes
split-specific passive facts inside that row. `SplitViewerSidebar` is
body-scoped, so the page rail starts below the header. `SplitViewerLegend`
lives inside `FileViewerSurface` above the document, which lets the rail dominate
the legend and document body without taking over the header.
`SplitViewerDocument` only frames the selected document node; it does not
receive hidden layout slots.

## Usage

`SplitViewer` is the easy API for a split result. It preassembles the same
provider and named parts; the source document remains an explicit prop, and
document coordination comes from `useSplitViewerDocumentControls`.

```tsx
export function EasyExample() {
  return (
    <SplitViewer source={source} result={result} document={<SplitDocument />} />
  )
}
```
