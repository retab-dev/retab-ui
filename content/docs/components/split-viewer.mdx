Renders a Retab split result: named subdocuments, each owning a set of pages.

<SplitViewerDemo />

## Viewer Composition

Compose split results from the split provider, viewer primitives, and named
split parts:

```tsx
function SplitDocument() {
  const controls = useSplitViewerDocumentControls()

  return (
    <PdfViewer
      ref={controls.setViewerHandle}
      source={source}
      bare
      onVisiblePageChange={controls.onCurrentPageChange}
      onScrollProgressChange={controls.onScrollProgressChange}
    />
  )
}

export function Example() {
  return (
    <SplitViewerProvider result={result}>
      <ViewerRoot>
        <SplitViewerHeader />
        <ViewerBody>
          <ViewerSidebar aria-label="Split pages">
            <SplitViewerPageRail />
          </ViewerSidebar>
          <ViewerSurface>
            <SplitViewerLegend />
            <SplitViewerDocument>
              <SplitDocument />
            </SplitViewerDocument>
          </ViewerSurface>
        </ViewerBody>
      </ViewerRoot>
    </SplitViewerProvider>
  )
}
```

`SplitViewerHeader` owns the full-width viewer title row.
`ViewerSidebar` is body-scoped, so the page rail starts below the
header. `SplitViewerLegend` lives inside `ViewerSurface` above the
document, which lets the rail dominate the legend and document body without
taking over the header.
`SplitViewerDocument` only frames the selected document child; it does not
receive hidden layout slots.

## Usage

`SplitViewer` is the easy API for a split result. It preassembles the same
provider and named parts; the source document remains an explicit child, and
document coordination comes from `useSplitViewerDocumentControls`.

```tsx
export function EasyExample() {
  return (
    <SplitViewer result={result}>
      <SplitDocument />
    </SplitViewer>
  )
}
```
