title: Pretext Markdown Viewer
description: An experimental Pretext-based Markdown viewer with continuous virtual rendering and a separate implementation path from the existing Markdown Viewer.
---

The Pretext Markdown Viewer is the new Markdown experiment built from the
Chenglou/Pretext text viewer path. It renders Markdown as a single continuous
document surface, keeps chunking internal to virtualization, and lets
React/GFM own the visible Markdown semantics.

## Installation

```bash
npx shadcn@latest add @retab/pretext-markdown-viewer
```

## Usage

```tsx
import { PretextMarkdownViewer } from "@/components/ui/pretext-markdown-viewer"

export function Example() {
  return (
    <PretextMarkdownViewer
      source={{
        kind: "text",
        text: "# Notes\n\nMarkdown should read in one continuous flow.",
        fileName: "notes.md",
        mimeType: "text/markdown",
      }}
    />
  )
}
```

URL and Blob sources use the same bounded text resource path as the Text Viewer:

```tsx
<PretextMarkdownViewer
  source={{
    kind: "url",
    url: "/samples/release-notes.md",
    fileName: "release-notes.md",
    mimeType: "text/markdown",
  }}
/>
```

## Why This Exists

The existing Markdown Viewer is React-Markdown based and accumulated a document
pagination model that was useful as a virtualization strategy but leaked into
the user experience. The Pretext Markdown Viewer starts from the opposite
direction: one continuous text/document layout, with virtualization as an
internal implementation detail.

This page documents the new component separately so the old Markdown Viewer can
remain stable while the Pretext path iterates toward feature completeness.

## Current Contract

- **Continuous rendering** - no page count, page frame, or page delimiter should be part of the Markdown user experience.
- **React/GFM rendering** - visible chunks render through React Markdown with GFM instead of a hand-built Markdown DOM renderer.
- **Pretext layout** - visible chunks start from block-aware, Pretext-informed height estimates, then measured heights feed back into the virtual frame.
- **Rendered/Text toggle** - rendered Markdown and source-faithful raw Markdown share one viewer frame and one controls.
- **Markdown-first routing** - sources are parsed as Markdown even when the file extension is generic text.
- **Source-line addressing** - `highlight` and `scrollToLineRange` keep using 1-based inclusive source-line ranges.
- **Stable heading anchors** - heading DOM IDs and virtual fragment navigation come from the same model-owned slug registry.
- **Reduced motion** - automatic viewer scrolls honor `prefers-reduced-motion` while explicit `behavior` options are preserved.
- **Restricted component markdown** - whitelisted components and component directives render through a schema-owned registry with quoted string props, enum validation, and Markdown children only where the component explicitly allows them.
- **Safe output** - unsupported Markdown should degrade to inert text or code output rather than executable DOM.
- **Separate implementation** - this component lives apart from `MarkdownDocumentViewer` and can make hard cutovers without compatibility shims.

## Implemented So Far

- Headings `h1` through `h6`, paragraphs, emphasis, inline code, lists, task markers, blockquotes, rules, tables, images, and fenced code render through React Markdown/GFM.
- Thematic breaks render as native `hr` separators with a stable `data-pretext-thematic-break` marker and document-level spacing.
- Virtual chunks are projected as continuous document content, without visible page shells, page labels, or inter-page gutters.
- Blank Markdown renders an explicit empty document state in the continuous canvas instead of a silent blank surface.
- The controls include a Rendered/Text toggle; Text mode is a virtualized raw Markdown source view with line numbers, source-line scrolling, source-line anchored mode switching, and a labelled keyboard-focusable source region for horizontal overflow.
- The controls include source-backed search that finds offscreen Markdown matches, reports result position, jumps previous/next, and highlights the matching source-line range in Rendered and Text modes.
- Source parsing, Pretext height estimation, and visible-window math are split across `pretext-markdown-parser`, `pretext-markdown-document-model`, `pretext-markdown-layout`, and `pretext-markdown-virtualizer`.
- Parser adapter coverage locks the current `marked` boundary for normalized tokens, unterminated code fences, malformed tables, malformed HTML, malformed links, and malformed frontmatter fences.
- The document model keeps semantic top-level Markdown block records with stable block IDs, source-line ranges, document-character offsets, offset lookup/intersection helpers, hostility flags, heading links, and owning virtual chunk indexes.
- The document model exports the single heading slug algorithm used for model IDs, DOM IDs, reserved-name protection, Unicode normalization, and duplicate suffixing.
- Layout estimates are derived from those block records, with separate line metrics and allowances for prose, headings, code, HTML, tables, rules, lists, frontmatter, and hostile blocks.
- The private virtualizer owns pixel-overscanned visible chunk projection, source-line scroll offset lookup with intra-chunk line positioning, rendered chunk source-highlight markers, and scroll-anchor capture/restore across measured height updates.
- Architecture tests keep the Pretext Markdown registry item and source imports independent from the old `markdown-document-viewer` modules.
- GitHub blockquote alert markers such as `> [!NOTE]`, `> [!TIP]`, `> [!IMPORTANT]`, `> [!WARNING]`, and `> [!CAUTION]` render as labelled alert surfaces with separated title/body regions, variant icons, and marker-free prose.
- Directive callouts such as `:::warning{title="Careful"}` render as callout surfaces.
- Component directives such as `::metric{label="Accuracy" value="98%"}`, `:badge[Stable]{tone="success"}`, `::image{src="/chart.png" alt="Chart"}`, `::video{src="/demo.mp4" label="Demo"}`, `::diagram{type="mermaid" source="graph TD; A-->B"}`, `:::accordion{title="More"}`, and nested `::::tabs` / `:::tab` blocks render through the same restricted component policy as component markdown.
- GitHub alerts and directive callouts render as labelled `note` regions; GitHub alerts use their alert title as the accessible region name, and code blocks and Mermaid diagrams expose accessible labels for the generated block and source fallback.
- Regular blockquotes keep semantic `blockquote` markup and support nested blockquotes plus contained list rhythm without becoming alert surfaces.
- YAML and TOML frontmatter are first-class frontmatter chunks with a metadata summary for top-level scalars, simple YAML/TOML lists and inline arrays, and TOML section scalars surfaced as dotted keys, plus a raw source-fidelity block instead of being rewritten into fenced code blocks; complex mappings and nested object arrays remain raw-source-only rather than being summarized, and unterminated or empty frontmatter fences stay ordinary Markdown.
- Heading IDs support duplicate suffixes, reserve DOM-clobbering names, decode common HTML entities before slugging, expose copy-link affordances, and local `#fragment` links, direct hash loads, hash changes, and back/forward fragment navigation scroll through the virtual document model.
- Links and images use a dedicated safe URL policy; protocol-relative URLs, control-character tricks, encoded unsafe schemes, Unicode delimiter confusables, backslash normalization tricks, non-HTTP image schemes, `data:` / `blob:` resources, and SVG/SVGZ image resources are rejected.
- Absolute HTTP(S) links open with `noopener noreferrer`, show an aria-hidden external-link cue, and expose a stable link-kind marker; fragments, relative links, root-relative links, and email links stay in the current browsing context, fragment links use distinct dotted underline styling, safe link titles are preserved as native tooltips, and links use a restrained visited-state color policy.
- Long prose tokens, links, table cells, inline code, definition-list terms, and restricted component labels use explicit overflow wrapping so pathological unbroken text does not widen the continuous viewer surface.
- Safe raw HTML is parsed through `rehype-raw` and narrowed by local policy before `rehype-sanitize`; `details`, `summary`, `figure`, `figcaption`, `caption`, `dl`, `dt`, `dd`, `mark`, `kbd`, `q`, `ins`, `abbr`, `time`, `cite`, `dfn`, `small`, `var`, `samp`, `sub`, and `sup` render through styled components, with safe HTML-only inline elements marked as raw-inline fallback surfaces. Unsafe tags, active raw inputs, SVG/script/style surfaces, unsafe attributes, and user-authored internal `data-pretext-*` metadata are removed before React rendering. User-authored raw HTML `id` and `name` attributes are prefixed with `user-content-` so they cannot clobber page globals, while model-owned heading IDs keep the viewer's stable slug contract.
- Markdown HTML comments are retained in the source model and Text mode but do not render or reserve visible layout height.
- Markdown language policy, URL policy, alert/callout transforms, restricted component parsing, prose transforms, and the sanitizer schema live in the dedicated `pretext-markdown-policy` module.
- Upstream SmartyPants typography transforms, upstream GitHub gemoji shortcode transforms, and Retab-specific arrow/fraction transforms apply to normal prose text while inline code stays literal.
- GFM autolink literals, bare email autolinks, strikethrough, soft line breaks, escaped control punctuation, ordered-list start values, and non-editable task-list checkboxes render through explicit Pretext Markdown components; autolinks expose stable link-form markers and literal monospace styling, strikethrough spans expose a stable marker with muted decoration styling, soft line breaks render through the `remark-breaks` policy with stable break markers, escaped Markdown control punctuation remains literal prose, and task-list items drop normal list markers and expose stable task-list item and checkbox state markers with checked-state accent styling.
- Loose list items, multi-paragraph list items, and nested ordered/unordered lists keep semantic list markup while using tighter nested-list rhythm.
- Conservative Markdown definition-list shorthand, written as `Term` followed by one or more `: description` lines, renders as semantic `dl` / `dt` / `dd` markup with stable Pretext markers; inline Markdown inside a single description line is preserved.
- Reference links and reference images resolve from document-wide definitions even when the definition lives outside the currently rendered virtual chunk.
- Restricted component markdown supports `<Metric label="Accuracy" value={98} />`, `<Badge label="Stable" tone="success" />`, `<Image src="/chart.png" alt="Chart" />`, `<Video src="/demo.mp4" label="Demo" controls={false} muted />`, `<Diagram type="mermaid" source="graph TD; A-->B" caption="Flow" />`, paired `<Callout kind="warning" title="Review">...</Callout>` blocks, and paired `<Accordion title="More details">...</Accordion>` blocks with safe Markdown children; restricted component directives additionally support nested `Tabs` / `Tab` blocks with safe Markdown panels. Tabs expose ARIA tab roles, selected-panel state, roving focus, Arrow key navigation, and Home/End navigation. The component registry owns allowed names, allowed props, typed string/number/boolean literal props, and enum values such as `Badge.tone`.
- Unknown JSX-like syntax, non-literal expression props, spread props, event handlers, component-specific unknown props, invalid enum values, and remote or namespaced components render as inert diagnostic component fallbacks with source previews. Import/export statements remain inert source-like text.
- Mermaid fenced blocks and restricted `Diagram` components render through the Mermaid package inside the viewer diagram surface, including common aliases such as `mmd`; Mermaid fence and component titles/captions render in the diagram header/caption, diagram bodies reserve deterministic source-derived height before Mermaid resolves, graph, flowchart, sequence, and state diagrams have built-in fallback SVG rendering for recoverable Mermaid layout/package failures, graph, sequence, state, class, ER, journey, Gantt, Git graph, timeline, mind map, and pie diagrams expose Mermaid-frontmatter-aware source-derived accessible summaries, Mermaid-only diagrams show source-backed loading state instead of a transient unsupported error, loading/error/ready states stay inside the same labelled keyboard-scrollable body region, failed diagrams keep the error and original source visible together, oversized diagram sources are refused before Mermaid runs and remain copyable, rendered SVG is sanitized before mounting with style/link/resource/animation SVG surfaces denied, parse/render failures stay contained in a non-crashing error/source state, and ready diagrams expose source and sanitized-SVG copy controls.
- Inline and block math render through `remark-math` and KaTeX with untrusted input, bounded expansion, bounded user-defined sizes, stable inline/block markers, and labelled keyboard-scrollable block math regions for wide equations.
- GFM footnotes render with labelled references, labelled backrefs, bidirectional fragment targets, a labelled footnotes section, and document-wide definition resolution across virtual chunks.
- Fenced code blocks show normalized language headers with common aliases for TypeScript, JavaScript, shell/terminal sessions, JSONC, YAML, Markdown, diff/patches, Dockerfile, Ruby, Python, and Mermaid fences, `title="..."` / `caption="..."` metadata, opt-in Pretty Code `showLineNumbers` / `showLineNumbers{n}` line numbers with accessible line labels, highlighted lines/chars, diff add/remove line styling, full-block and selected-code copy controls with copied/failed states, a labelled keyboard-focusable horizontal source region, and `rehype-pretty-code` syntax highlighting.
- GFM tables render inline cell Markdown, preserve left/center/right alignment with tabular numeric styling for right-aligned cells, support safe raw HTML captions, use a keyboard-focusable horizontal scroll region with Arrow/Home/End controls, patch deterministic header/cell associations plus row/column count and index annotations, and include a copy action that writes rendered cells as TSV or the selected table text when the selection is inside the table.
- Images render through a safe Markdown image surface with blocked, loading, ready, failed, and retry states, title captions associated through `aria-describedby`, lazy loading, max-width containment, decoded aspect-ratio stabilization, and SVG/data/blob resource blocking; restricted videos render through the same safe media URL policy with controls, metadata preload, captions, and blocked/failed states.
- The controls include copy and download actions for the full raw Markdown source, including shared copied/failed clipboard status handling across source, block, table, code, heading, and diagram copy controls, inline download failure status for generated Markdown payloads, plus inline text, URL fallback, URL download metadata, Blob download metadata, and local Blob object URLs.
- Oversized code, table, paragraph, list, and HTML payloads are flagged as hostile chunks, isolated from neighboring prose, given cheap deterministic layout estimates, and rendered as bounded source previews with full-source copy instead of mounting the entire rich Markdown subtree.
- URL, Blob, and inline text sources load through the existing bounded text resource layer.
- File Viewer routes Markdown URL sources, Blob sources, inline text sources, and MIME-only Markdown sources through `PretextMarkdownViewer`.
- A dedicated `/view/pretext-markdown-viewer` browser smoke route exercises the rich demo and verifies continuous rendering, bounded mounted chunks, no page chrome, no document-level horizontal overflow, rendered/source mode switching, rendered/source highlight markers, stable scroll after measurement and async Mermaid/image settling, direct hash loads, local fragment clicks, footnote ref/backref navigation, browser back/forward fragment restoration, Markdown/raw-HTML link target and rel policy, narrow mobile layout, and dark-mode rendering.
- The registry item is separate: `pretext-markdown-viewer`, and its generated artifact has a transitive install-tree import-closure smoke test against registry dependencies, alias imports, declared package dependencies, and a local `shadcn add @retab/pretext-markdown-viewer` CLI install smoke.

## Not Complete Yet

The missing work is tracked in the repository file
`design/pretext-markdown-viewer-missing-inventory.md`. The largest gaps are
arbitrary MDX execution, broader GitHub alert visual/a11y verification,
directive semantics beyond callouts, nested frontmatter metadata policy, full
accessibility verification, syntax highlighting polish, raw HTML schema polish,
hostile-block inner virtualization, source-mode selection polish, native browser
find behavior with virtualized offscreen content, image
retry/dimension metadata polish, published registry endpoint verification, and
broader integration rollout beyond File Viewer routing.

## Unsupported Syntax

The Pretext Markdown Viewer intentionally does not execute arbitrary MDX. JSX-like
component syntax is restricted to the whitelisted component registry,
serializable string/number/boolean literal props, and safe Markdown children
where the component allows them. Unknown components, non-literal expression
props, spread props, event handlers, invalid enum values, remote or namespaced
components, and unsafe directive props render as inert diagnostic fallbacks with
source previews. Import/export statements render as inert source-like text.

Mermaid rendering uses the Mermaid package with strict security settings,
disabled flowchart HTML labels, bounded width behavior, and built-in
graph/flowchart/sequence/state fallback SVG rendering inside the viewer diagram
surface, then sanitizes the produced SVG before mounting it. The SVG mount
boundary denies active tags, embedded resources, SVG links, animation, and style
surfaces, and prefixes SVG `id` / `name` values before mounting.
Invalid diagrams or browser rendering failures stay contained in a non-crashing
error/source surface while pre-layout dimension estimation remains open.

Large hostile blocks are isolated and rendered through bounded source previews,
but they are not internally virtualized as rich Markdown yet. Extremely large
code fences, generated tables, and very long paragraphs preserve source access
while the broader large-block virtualization work remains open.

## Migration Plan

Use `PretextMarkdownViewer` for Markdown files and inline Markdown sources where
continuous document flow matters. Keep the existing Markdown Viewer available
for stable legacy routes until the acceptance checklist below is complete.

Use `TextViewer` for prose text that is not Markdown, and use `CodeViewer` for
logs, JSON, source code, and line-oriented files. File Viewer routing should
continue to choose the viewer by content semantics rather than by a generic text
fallback.

The old paged Markdown Viewer can be removed only after the Pretext path has
browser coverage for long documents, rich blocks, broader mobile/dark visual
states, registry installation, and source-line/fragment navigation across
realistic files.

## Replacement Checklist

- No visible page labels, page frames, page gaps, or page delimiters in rendered Markdown.
- Bounded mounted content for large Markdown files, with pixel overscan and measured-height correction.
- Stable scroll anchors across measurement updates, width changes, zoom changes, and font readiness.
- Source-line highlighting and `scrollToLineRange` work in rendered and Text modes; rendered chunks that intersect the highlighted range expose stable highlight data attributes and an accessible region label.
- Heading IDs, hash loads, hash changes, and local fragment clicks use the same model-owned slug registry.
- GFM tables, task lists, autolinks, strikethrough, footnotes, math, safe raw HTML, code blocks, alerts, images, and restricted components have focused regression coverage.
- Unsafe links, images, HTML, directives, and component props are blocked or rendered inert.
- Browser smoke tests prove continuous rendering, no overflow, no flicker, and no hydration skeleton for inline demos.
- Registry artifact install/import smoke tests pass for `pretext-markdown-viewer`.
- File Viewer routes Markdown URL, Blob, inline text, and MIME-only sources to this viewer.

## Props

| Prop        | Type                    | Description                                                                |
| ----------- | ----------------------- | -------------------------------------------------------------------------- |
| `source`    | `TextDocumentSource`    | Required source descriptor. Supports URL, Blob, and inline text resources. |
| `className` | `string`                | Optional class on the viewer container.                                    |
| `controls`  | `boolean`               | Show word count, zoom controls, and download action. Defaults to `true`.   |
| `highlight` | `TextLineRange \| null` | 1-based inclusive source-line range to highlight.                          |
| `bare`      | `boolean`               | Drop the outer border/background so the viewer fills its container.        |
| `maxBytes`  | `number`                | Maximum text payload size accepted by the viewer.                          |
| `maxLines`  | `number`                | Maximum number of source lines accepted by the viewer.                     |

## Ref

```tsx
import * as React from "react"

import {
  PretextMarkdownViewer,
  type TextViewerHandle,
} from "@/components/ui/pretext-markdown-viewer"

export function Example() {
  const viewerRef = React.useRef<TextViewerHandle>(null)

  return (
    <PretextMarkdownViewer
      ref={viewerRef}
      source={{ kind: "text", text: "# Alpha\n\n## Beta\n\nGamma" }}
      highlight={{ start: 3, end: 3 }}
    />
  )
}
```

`scrollToLineRange(range, options?)` scrolls any normalized source-line range
into view, even when that source line is outside the currently mounted virtual
window.
